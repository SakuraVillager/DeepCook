### 2.1 内容（100 道新菜谱）

- 按地域分批产出：中式 40（叠加原有 12 → 52）、日式 15、韩式 12、美式 10、欧式 10、东南亚 8、其他 5（印度、墨西哥、中东、北非、土耳其）。
- 每道都含：一句话简介、1–3 个菜式分类、用时、1–5 难度、份量、5–12 项材料、4–6 个步骤（步骤标题 + 操作正文 + 观察提示）、注意事项、来源信息。
- 文字为自编演示内容，参考公开菜谱资料整理，未经试做验证，界面与文档都标明了这一点。
- 缺元素统一写「无」：准备事项、注意事项、观察提示没有内容时写 `"无"`，界面隐藏该项，不渲染「观察提示：无」这类空行。数值字段（用时/难度）缺失仍为 `null`，界面显示「—」。
- 排版与原有 12 道统一：范围用 `—`、数字与汉字之间留空格、正文以句号结尾。
- 来源链接：19 个候选参考页里只保留能直接访问的 11 个（https），其余留空，不展示打不开的链接，也不编造 URL。

### 2.2 数据模型（第 3 版格式）

- `Recipe.region`：必填，白名单 7 个地域，构造时校验（`Recipe.init`）。
- `categories` 只描述菜式：家常菜、快手菜、素食、肉类、海鲜、汤羹、主食、面食、烘焙甜点、早餐、沙拉，构造时校验白名单且不能为空。地域**不**写进分类，避免一个维度记两次。
- `RecipeCategoryOptions` = 全部 + 7 地域 + 11 菜式分类，**首页 chip 行和搜索分类下拉共用这一个列表**，保证两个入口永远一致。
- 无占位：`Recipe.preparationItems`、`Recipe.noteItems`、`RecipeStep.visibleCue` 三个派生属性负责过滤 `"无"`，UI 只读这三个。
- 过滤逻辑：一个选择值既可能是地域也可能是菜式——是地域则按 `region` 精确匹配，是菜式则按 `categories` 匹配，`全部` 放行；文本搜索也匹配地域名（输入「韩式」可用）。

### 2.3 界面

- **卡片**：封面左上角地域徽标（surface 88% 不透明、8dp 圆角、labelSmall、无障碍描述「地域 X」）。
- **列表行与详情**：复用 `RecipeMetadata`，在用时、难度之后追加地域项（Public 图标），详情不额外占一行。
- **首页**：分类 chip 行改为 `RecipeCategoryOptions`，地域在前、菜式在后，可横向滚动，点击进入对应筛选的搜索页。
- **搜索页**：分类下拉同一列表；选中地域按 `region` 过滤，选中菜式按 `categories` 过滤。
- **详情**：分段索引改为按当前可见分段推算，修掉了原先「假设前 3 个 item 固定、下标从 3 硬编码」的隐患——那段逻辑在隐藏「准备/注意」时会静默错位。
- **设置**：「内容与来源」页更新为 112 道 / 7 地域、图片真实来源与未配图说明、地域标签说明。

### 2.4 工具

- `tools/validate_content.py`（新增，只读）：校验 ID 唯一、地域/分类白名单、每道 3–6 步、材料 3–14 项、步骤 ID 与 `order`、`ingredientRefs` 指向、封面文件存在、地域分布、精选恰好 6 道、「鲈鱼」唯一（UI 测试依赖）；**另外校验 `photo_sources.json` 与 assets 一致**（每张封面都有署名、清单里没有缺失或多余文件）。
- `tools/prepare_content.py`（改造）：只重建最初 12 道，且必须设置环境变量 `DEEPCOOK_REBUILD_CONTENT=1` 才允许运行，避免一句命令覆盖掉扩充内容；同时同步到第 3 版格式与「无」约定。

| HowToCook | 4 | Unlicense | 固定 commit，同一仓库也是原有 12 张的来源 |

筛选规则（后续补图请沿用）：

1. **只用授权明确的图库**，不从下厨房/百度/摄图网等版权站抓图；
2. **只接受菜名级匹配**，不接受「沾边的食材图」（所以 `pho`→"photo"、`lamb`→"flambe"、`oden`→"wooden" 这类子串误配全部丢弃）；
3. **逐张肉眼核对**：剔除带第三方水印的照片、剔除与菜品明显不符的照片、宁可留空。

本轮剔除记录：HowToCook 的「水煮牛肉」原图带 `www.zhms.cn` 水印（该仓库也收读者投稿，会有这类图）；FoodiesFeed 的烤羊肉串候选带 dreamstime 水印；HowToCook 的提拉米苏原图过糊，改用图库版本。希腊沙拉、咖喱叻沙、天妇罗等因找不到「确实就是这道菜」的合规照片，保持占位图。

## 5. 已知缺口与后续建议（按优先级）

1. **74 道仍然没有配图**（35 道中式、14 道日式、9 道韩式等）。补齐的前提是换一个能访问 Wikimedia Commons / Openverse 的网络（这两个库是中式/日韩菜最好的开放图片来源，本机网络直接超时），或由人工提供授权图片（按 `photos/<recipeId>.jpg` 放入即可批量接入）。
2. **原有 12 张配图质量偏弱**：红烧肉那张烧进了日期水印（`2022.02.01`）、白灼菜心是一张小图、麻婆豆腐与番茄豆腐汤偏糊。建议按同一标准（授权明确 + 菜名匹配 + 肉眼核对）替换，替换后同步 `photo_sources.json`。
3. **测试与数据耦合**：以后再增删菜谱，必须同步 §2.6 列出的数字断言与 `EXPECTED_REGIONS`，否则 UI 测试会失败。
4. **继续扩内容时的约定**：地域只能取 7 个白名单值；分类只能取 11 个菜式；缺的内容写「无」；步骤 ID 用 `<recipeId>-sN`、材料 ID 用 `i0..in`；`featured` 必须恰好 6 道；整个内容里「鲈鱼」只能出现一次（UI 测试依赖）。改完跑 `python tools/validate_content.py`。
5. **首页 chip 行有 19 个值**（全部 + 7 地域 + 11 菜式）。目前是单行横向滚动，地域排在前面；如果产品上觉得太长，可以改成「地域」「菜式」两行，或在首页只放地域。这是待定项，没有实施。
6. **口径待统一**：卡片徽标显示地域文字，列表/详情显示「地域」元数据项，两处视觉形式不同（出于空间考虑），如果觉得不一致可以统一成徽标。

### 9.3 AI 的定位与边界

一句话：**锅在火上、手在油里的时候，唯一不用你腾出手的助手**——不是菜谱 App 加个聊天框。它要「知道语境」：知道你在做哪道菜、第几步、你不吃什么、上次你说过要少放盐。

明确不做：

- **不做摄像头实时跟步**（锅盖遮挡、蒸汽、逆光、机位都会失准；误判一次就没人再信进度）；
- 不拿模型输出冒充「已试做验证」的菜谱；
- 不用品牌唤醒词（「小爱小爱」是小米的），默认「小厨小厨」。

### 9.4 已定的决策

| 决策 | 结论 |
| --- | --- |
| 主模型 | **智谱 `glm-4.7-flash`**（免费、国内直连、OpenAI 兼容、200K 上下文、支持工具调用） |
| 视觉模型 | `glm-4.6v-flash`（免费）；备选 `MiniCPM-V-4.7-35B-A3B` |
| 唤醒词 | 固定「小厨小厨」，端侧识别；自定义留到以后（换词要重训模型） |
| Key 归属 | **暂缓**：开发期放本机，上线前必须在「用户自带 BYOK」与「我们代理」之间二选一 |
| 多菜上限 | 最多 3 道，超过只提示不拦 |
| 做菜页 | 与「分步阅读」共用同一套步骤渲染，做菜模式是它的一个模式 |
| 后台计时 | 要：做菜会话期间起前台服务（与麦克风共用），退出即停 |
| 口味记忆 | 按菜记录；手写或对 AI 说；**AI 写入前先确认** |
| 多菜排程 | **代码排程、模型写文案**；模型不决定顺序 |
| 摄像头 | 只做单帧「看一眼」 |

### 9.5 三个原想法的最终结论

1. **摄像头自动跟步 → 降级**。改为单帧「看一眼」（拍一张问颜色/收汁/熟度）、声音事件（油爆/沸腾，仅建议）、用户一句话推进度（「下锅了」）。
2. **语音短答 → 主场景**。端侧唤醒 + 回答 ≤2 句（先数字后理由）+ 首字 1.5 秒 + 断网读本地步骤 + 前台服务常驻通知。~~首问免唤醒~~ 已于 2026-11 决定不做。
3. **AI 建菜谱 → 接在 `RecipeLookup` 后面**。顺序固定：本地 494 道索引 → AI 联网检索 → 手填；AI 产出只进草稿，必须过 `RecipeDraft.problems()` + 人工确认；只抽取要点改写并保留来源。

### 9.6 三个新板块

**口味记忆（P0）**

- 「我的」页新增一栏，按菜列出备注（例：「红烧肉 · 少放点盐，冰糖减半」）。
- 写入方式：手写；或对 AI 说（AI 先解析菜名并回一句确认；做菜中说「记一笔：少放盐」则用当前菜，不解析）。
- 用起来：下次做同一道菜时，做菜页开头置顶提示，并注入每次提问的上下文。
- 分层：**忌口是全局的（不吃香菜），口味记忆是这道菜的修正（这道菜少放盐）**；冲突时以这道菜备注为准。
- 数据：`DishNote(recipeId, text, updatedAt, source, stepId?)`，存 `UserData.dishNotes`；删除自建菜谱要级联删除。

**多菜时间线（P2）**

- 新入口「今晚菜单」：勾 2–3 道菜 → 生成合并清单（几点做什么）→ 双视图预览（时间线 / 按菜）→ 可拖动可锁定 → 「开始做菜」。
- 每项都带原步骤引用 `(recipeId, stepId)`，点进去能回到原文。
- **前置**：`RecipeStep` 现在既没有 `minutes`，也没有「占不占手」，必须先补（494 道 × 约 8.5 步 ≈ 4186 步）。
- 排程由代码算（步骤顺序固定、同一时刻只能有一个主动步骤、被动步骤可并行），模型只把相邻步骤写成一句人话。
- 失败退路：模型超时或结果不可信 → 退回「按菜依次做」。

**做菜模式（P0）**

- 入口：菜谱详情底部、我的菜谱列表、今晚菜单的合并清单，都放「开始做菜」。
- 页面：大字号当前步骤 + 上下步 + 计时器 + AI 入口 + 口味记忆提示条；屏幕常亮沿用现有设置。
- 计时器：手动点，或一句话设定（「炖十分钟」→ 600 秒）；支持加时、取消、多个并存；到点响铃 + 语音 + 通知（切后台也能收到）。

### 9.7 数据模型草案

```kotlin
DishNote(recipeId, text, updatedAt, source, stepId?)            // 口味记忆
RecipeStep(+ minutes: Int?, + kind: ACTIVE | PASSIVE)            // 多菜时间线的前提
CookTask(recipeId, stepId?, text, minutes, kind, offsetMinutes)  // 合并后的一项
CookSession(id, recipeIds, tasks, createdAt)                     // 一次做菜，可恢复
```

### 9.8 供应商与免费额度（2026-11 实测）

本机（与手机同一网络）连通性：

| 服务 | 结果 |
| --- | --- |
| 智谱 `open.bigmodel.cn` | ✅ 116 ms |
| 硅基流动 `api.siliconflow.cn` | ✅ 24 ms |
| 阿里 `dashscope.aliyuncs.com` | ✅ 通 |
| 火山方舟 `ark.cn-beijing.volces.com` | ✅ 通 |
| Moonshot / DeepSeek / OpenRouter / Groq | ✅ 通（OpenRouter 偏慢） |
| **Google Gemini** | ❌ 超时，直连不可用 |

- **智谱**：`glm-4.7-flash`（30B 级 MoE，200K 上下文）与 `glm-4.6v-flash` 输入输出全免费；新用户另送 2000 万 tokens；**免费模型并发很低（社区实测约 1）**，不能放在需要并行的关键路径上。
- **一个 API Key 可调所有模型**，靠请求体里的 `model` 切换；免费与付费共用 key，额度按模型分别计算。**例外**：GLM Coding Plan 走专属 Anthropic 端点，别混用。
- **OpenRouter** 免费模型：20 次/分、50 次/天（累计充值满 10 美元才升到 1000 次/天）。
- **阿里百炼**：每模型 100 万 tokens、90 天，仅北京地域；**2026-10-29 起一批文本模型（qwen-flash/plus/max、deepseek 等）已下架免费额度**，只能当备用。
- 选型结论：主用智谱；`MiniCPM-V-4.7-35B-A3B`（免费、MoE 3B 激活、能看图）做视觉与备选；`MiniCPM5-2B` 只做「读步骤」类极速兜底。
