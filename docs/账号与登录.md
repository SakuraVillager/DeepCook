# 账号与登录

本版给 DeepCook 加了一套本地账号。目标不是做一套注册中心，而是把网页登录那套流程原样搬到手机上：
先有身份，再进应用；表单逐项校验；登录态重启后仍在；随时可以改密码和退出。

## 一、流程

```
启动
 └─ 读 account.json（这期间显示进度圈，不闪登录页）
     ├─ 没有登录态 → 登录页
     │    ├─ 手机号 + 密码 → 登录成功 ─┐
     │    ├─ 立即注册 → 注册页 ────────┤
     │    └─ 忘记密码 → 重置页 ────────┤（改完回登录页）
     │                                ↓
     └─ 有登录态 ─────────────→ 首次引导（没填过）→ 首页
                                        ↓
                          我的 → 用户信息 → 账号与安全
                                        ├─ 修改密码
                                        └─ 退出登录 → 回到登录页
```

要点：

- **门在外层**。登录页不是导航图里的一个目的地，而是 `DeepCookApp` 里挡住整个应用壳的一层判断。
  没有登录态时，`NavHost` 根本不会被组合，所以不存在“绕过登录直接看菜谱”的路径。
- **登录后才走引导**。注册成功即视为登录，接着进入首次引导；填过引导的老账号直接进首页。
- **退出后换一套导航栈**。`nav` 用 `accountId` 做 key，退出登录时导航控制器整体重建，
  下次登录回到首页，而不会停在上一个人正在看的详情页。
- **退出不清数据**。收藏、我的菜谱、饮食偏好、设置都属于这台手机，退出登录只清登录态。
  退出前会明确告诉用户这一点，避免误以为会“注销账号”。

## 二、页面

| 页面 | 位置 | 说明 |
| --- | --- | --- |
| 登录 | `feature/auth/AuthScreens.kt` | 手机号、密码、忘记密码、立即注册 |
| 注册 | 同上（同一张卡切换） | 手机号、密码、确认密码、勾选确认 |
| 重置密码 | 同上 | 手机号、新密码、确认新密码 |
| 账号与安全 | `feature/auth/AccountScreen.kt` | 手机号（打码）、注册时间、上次登录、修改密码、退出登录 |
| 用户信息里的入口 | `feature/profile/ProfileInfoScreen.kt` | “账号与安全 · 138****8000” |

设计沿用现有视觉：暖黄底色、白色 16–20dp 圆角卡片、1dp 细边框、52dp 主按钮，
深色模式下卡片换成 `surfaceContainerLow`，边框改用 `outlineVariant`，与菜谱卡片同一套规则。

登录/注册/重置是同一张卡片的三个状态，不做页面转场——切换瞬间完成，不会出现两张表单同时在场
（同时在场会让无障碍朗读和自动化测试都拿到重复的输入框）。

## 三、校验规则

| 字段 | 规则 | 提示 |
| --- | --- | --- |
| 手机号 | 11 位，`1[3-9]` 开头；自动去掉空格、短横线、`+86` | 请输入 11 位手机号 |
| 密码（登录） | 非空 | 请输入密码 |
| 密码（注册/重置/改密） | 8–32 位，不含空格，同时含字母和数字 | 密码至少 8 位 / 密码至少包含一个字母 … |
| 确认密码 | 与密码一致 | 两次输入的密码不一致 |
| 注册确认项 | 必须勾选 | 请先确认账号只保存在这台手机上 |

校验在 `AuthViewModel.submit()` 里一次算完，错误挂到对应字段上，改动该字段即清除该字段的错误。
请求级别的失败（手机号未注册、密码错误、锁定）显示在按钮上方。

## 四、数据与安全

`account.json`（DataStore，`data/AuthRepository.kt`）：

```json
{
  "accounts": [
    {
      "id": "uuid",
      "phone": "13800138000",
      "salt": "base64(16 字节随机盐)",
      "passwordHash": "base64(PBKDF2-HMAC-SHA256, 256 位)",
      "iterations": 120000,
      "createdAt": 1760000000000,
      "lastLoginAt": 1760000000000
    }
  ],
  "session": { "accountId": "uuid", "phone": "13800138000", "issuedAt": 1760000000000 }
}
```

- **不存明文密码**。PBKDF2-HMAC-SHA256，每账号独立随机盐，12 万轮（Android 8 上约 0.2 秒），
  哈希在 `Dispatchers.Default` 上算，不卡输入。
- **恒定时间比较**。`MessageDigest.isEqual` 比对哈希，避免用响应时间试探密码。
- **登录失败锁定**。同一手机号连续错 5 次锁 60 秒，倒计时写在提示里。计数只放在内存，
  重启即清空——对本地账号够用，也不往 `account.json` 里塞攻击痕迹。
- **统一的错误话术**。登录失败只说“手机号或密码不正确”，不区分手机号是否存在。
- **文件坏了不清空**。`AuthStateSerializer` 抛 `CorruptionException`，界面提示无法读取，
  原文件保留，和 `user_data.json` 的处理一致。

## 五、留好的云端接缝

界面只依赖两样东西：`AuthRepository` 接口，和它的 `session` / `account` 两个 Flow。
接云时只需要：

1. 新写一个 `RemoteAuthRepository : AuthRepository`，把 `register` / `login` / `resetPassword` /
   `changePassword` / `logout` 换成网络请求，`session` 用令牌或本地缓存映射成同一个 `Session`。
2. 在 `AppContainer` 里把 `val auth: AuthRepository = LocalAuthRepository(...)` 换掉。

页面、`AuthViewModel`、`DeepCookApp` 的门禁逻辑都不用改。失败原因沿用 `AuthFailure`，
需要新增（比如网络不可用、验证码错误）就在枚举里加一项，并在 `AuthViewModel` 里按需展示。

## 七、已知限制

- **账号不联网**。没有短信验证码，所以“忘记密码”只对**这台手机上已注册**的号码有效；
  它是本地重设，不是身份验证。真要防冒用，必须接云端 + 短信。
- **收藏与设置是设备级的**。一台手机一个厨房：换账号登录看到的是同一份收藏。
  这是为了不让升级时丢数据，也是本版最明显的一处边界。要做多账号隔离，
  下一步把 `userData` / `userRecipes` / `avatars` 换成按 `accountId` 分文件的实现，
  再把 `account.json` 里的历史数据迁移给第一个账号。
- **没有“删除账号”**。本地文件随应用数据一起删除；云端版需要单独做注销流程。
- **没有生物识别/自动填充**。`OutlinedTextField` 已声明 `KeyboardType.Password`，
  系统的密码管理器可以识别，但应用没有主动对接。
