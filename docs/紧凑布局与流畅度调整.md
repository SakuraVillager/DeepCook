# DeepCook 0.1.2：紧凑布局、步骤重排与转场性能

## 本次调整

- 首页缩小顶部内容边距，主标题与说明组成一个紧凑区块，分类和精选之间不再叠加大间距。
- 详情的用时、难度和份量并排排列，简介与示例说明使用 6dp 间隔。分段栏仅在吸顶后预留状态栏高度。
- 材料表统一组织行与分隔线，移除重复的区块间距；每行上下边距 7dp，用量右对齐，保留大字体自然换行。
- 烹饪步骤使用统一的编号卡片：标题和放大入口在同一行，操作正文为主体，观察提示为次要信息。去掉重复分隔线和独占一行的放大按钮。
- 分步阅读固定进度和底部按钮，中间只显示当前步骤的主操作卡片与必要提示，切换步骤后正文回到顶部；目录、指定步骤进入、重建恢复和返回定位仍可用。

## 流畅度处理

原版详情在进入动画开始时就写入最近浏览，写入后的全局状态更新会与页面初始化和转场重叠。本版等导航条目的生命周期恢复至 RESUMED 后再记录，避免这次刷新发生在进入动画期间。状态栏颜色仅在相关状态变化时更新。页面导航同时防止连续点击重复入栈，重复点击当前主入口也不再重建页面。

原交付为包含调试工具且未启用 R8 的 Debug APK。新增 `preview` 构建，使用与 Release 一致的 R8/资源缩减和库自带基线配置，关闭调试，使用本地开发密钥签名。优化构建与 Debug 构建共用应用 ID 和签名，可直接覆盖安装；本地收藏和偏好不受影响。

动画本身仍沿用 Mihon 的 200ms Fade Through 与 300ms/30dp Shared Axis X。

Android 官方也要求在优化构建中评价 Compose 的运行性能：[Compose 性能说明](https://developer.android.com/develop/ui/compose/performance)。此处性能测试保留完整动画，不通过关闭或缩短动画掩盖耗时。

- `assembleDebug`、`assemblePreview`、JVM 测试、Android UI 测试及 Android Lint。
- UI 回归增加指定步骤卡片进入与返回、来源区块可达、连续双击避免重复详情页。
- 在专用 Android 15 模拟器上使用 `tools/measure_navigation.py`，重复切换我的/找菜、进入详情/阅读与返回；原始 `gfxinfo` 及摘要保存在 `artifacts/reports/polish-0.1.2`。
- 软件渲染模拟器的帧耗时用于发现回归和比较同机样本，不能代替用户手机上的帧率保证。

2026-10-16 自动验证结果：7 项 JVM 单元测试、11 项 Android 模拟器测试通过，Debug/Preview 构建通过；ktlint 和 `git diff --check` 通过；Lint 为 0 错误、6 条 SDK/依赖升级提示。已核对优化包签名、应用版本和打包的 `baseline.prof` / `baseline.profm`。

页面截图覆盖约 412dp、360dp 和 900dp 宽屏，系统字体 1.0/1.3/2.0，以及明暗主题。实际首页、详情、步骤列表和阅读页组合预览位于 `artifacts/screenshots/preview.png`。

## 帧耗时对照

停止构建守护进程后，在同一模拟器、720×1600 / 280dpi（约 411dp 宽）、完整系统动画、同一操作序列下分别全新安装。每个样本包含一次初始采样和四轮重复导航。以下是本次样本，不是设备性能保证。

| --- | --- | --- | --- | --- |
| 0.1.1 Debug，初始采样 | 174 | 5.17% | 48ms | 101ms |
| 0.1.2 Preview，初始采样 | 182 | 3.85% | 27ms | 44ms |
| 0.1.1 Debug，重复导航 | 716 | 4.19% | 29ms | 65ms |
| 0.1.2 Preview，重复导航 | 724 | 3.31% | 28ms | 32ms |

原始数据对应报告目录中的 `controlled-before-debug-*` 与 `controlled-after-preview-*`。平均体感仍可能随硬件和系统负载变化；此样本主要显示耗时较长的帧有所减少。此前 1080p 软件渲染的几轮记录受主机内存压力影响明显，均保留供排查，不用于上述对照或推算手机帧率。
