# 我的菜谱（0.3.0 合并版）

入口为“我的 → 我的菜谱”，个人中心也提供“添加菜谱”。填写菜名后可以补全资料、手动编辑、选取相册封面，再保存到当前设备。

## 资料补全

优先从随包 494 道菜谱中按名称、别名匹配，已有资料不需要联网。本地没有匹配项时，才通过固定版本 HowToCook 索引请求公开 Markdown 页面；网络失败不影响手动填写。不会上传用户的材料、照片或设备信息。

所有补全（包括第一次）只填空白字段。用户写过的简介、份量、材料、步骤和选定的封面保留；补全期间改名会取消过期查找，旧结果不会落到新菜名上。提示会注明匹配的菜名与来源，仍需核对。

未知地域、用时、难度、份量不默认补成“中式、1 人份”。保存后的缺失参数显示“无”。继承的署名、许可、源链接、别名和风味标签保留，不把 Based Cooking 或项目示例错误标成 HowToCook。

## 保存和放弃

- 保存完成后才退出。写入失败留在表单，保留草稿与旧封面，允许重试；保存和图片导入期间禁止重复保存。
- 表单草稿通过 SavedStateHandle 保存，旋转与系统恢复时可继续编辑。
- 只有真正改过内容时返回才提示放弃；打开现有菜谱但未修改时可以直接返回。
- 新封面先作为临时文件导入。取消编辑只清理本次临时图片，原菜谱仍引用原图；成功写入菜谱后再清理被替换的旧图。
- 封面统一处理为 1200×900 JPEG，支持 EXIF 旋转和镜像，解码前限制像素与最长边，检查编码是否成功。只允许删除私有 covers 目录内符合命名规则的文件。
- 编辑保留菜谱、材料与已有步骤的 ID，新增行避免与保留行撞号；菜谱版本递增。
- 保存至少需要菜名、一项材料和有正文的步骤；不能只写步骤标题。未知参数可以留空。

## 存储与错误

用户菜谱单独存入 DataStore `user_recipes.json`，内置菜谱仍是只读 assets。用户菜谱 ID 以完整 UUID 的 `user-` 前缀生成，存储层拒绝覆盖内置 ID、重复 ID、空正文等非法内容。

用户菜谱文件损坏时保留原文件并显示可重试提示，内置菜谱照常可用。删除流程先清理对应收藏/浏览关系，再删除菜谱，成功后清理其封面；操作中断会提示重试，不声称多份文件已经原子回滚。

个人菜谱与内置内容共用搜索、收藏、详情及分步阅读。不会自动变为首页精选。删除不会影响其他菜谱与设置。

## 相关实现与验证

- `RecipeDraft`：表单、校验、ID 与来源保留。
- `CatalogFirstLookup`：本地优先查找；`HowToCookLookup`：可选的公开页面回退。
- `RecipeEditorViewModel`：补全竞争、草稿、提交状态与临时封面生命周期。
- `UserRecipeStore`：独立存储与完整性校验；`CoverStore`：受限图像解码、方向修正和私有文件。
- 单元测试覆盖空白补全、过期请求、失败重试、取消封面、草稿恢复、来源和稳定 ID；模拟器覆盖增改删全路径及实际图片文件。
