## 三、必须先决策的风险（动手前必须处理）

### 风险 1：两套计时器（最严重）

| 本地 | 远端 |
| --- | --- |
| `data/CookTimerService.kt`（前台 Service + 通知 + 响铃） | `data/TimerManager.kt`（通知 + 响铃 + SCHEDULE_EXACT_ALARM） |
| `data/CookSessionStore.kt` | `feature/timer/CookingTimers.kt`、`TimerReceiver.kt` |

两者都用 Notification + Ringtone + 前台服务，功能高度重叠。直接合会得到**两个计时通道**，可能出现重复响铃、两条通知、两个前台服务。**必须二选一或明确分工**。

### 风险 2：`Avatars.save()` 接口漂移（无文本冲突，但会编译失败）

```
本地：suspend fun save(bitmap: Bitmap, previous: String?): String?
远端：suspend fun save(bitmap: Bitmap): String?
```

`AvatarStore.kt` 不在冲突列表里，说明 git 会**自动合并成其中一边**——但另一边的调用点会全部编译失败。这类"静默语义冲突"只能靠编译发现，**不能只靠解决冲突标记判断完成**。

### 风险 3：`recipes.json` 脚本合并不当会丢数据

40 个冲突块全是同一模式：

```jsonc
// 本地：给步骤加了时长与类型
"text": "...", "minutes": 4, "kind": "ACTIVE"
// 远端：给同一步骤加了配图
"text": "...", "image": "photos/step-three-treasures-09.jpg"
```

字段互补、不矛盾，正确解法是合并三个字段。逐块手工点 40 次容易漏，应写脚本。
